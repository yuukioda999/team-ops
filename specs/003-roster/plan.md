# 003 名簿:実装計画

spec.md の受け入れ基準をどう作るかを決める。判断が要る点は「判断が要る点」にまとめた。小田の判断を受けてから ADR を書き、tasks.md と実装に進む。

## 全体の流れ

```
[代表・役員] 名簿 → 選手を登録(表示名・学年・背番号)→ 保護者(保護者の役割を持つメンバー)を紐づける
             または CSV を選ぶ → 確認(件数と先頭10行、エラーなら行・列・理由の一覧)→ 確定で一括登録
[コーチ] 名簿 → 全選手を見る(学年・背番号で絞り込み)
[保護者] 名簿 → 自分に紐づく選手だけを見る
すべての閲覧・変更・取り込みを監査ログに残す(ADR-0012)
```

## 判断が要る点(推奨付き)

### 判断1. 同じ表示名・同じ学年の重複の見つけ方(AC-003-03)

選手の表示名は暗号化して保存する(ADR-0003)ので、DB の検索では同じ名前を探せない。

| 案 | 内容 |
|---|---|
| **A(推奨)** | 登録のたびに、そのチームの同じ学年の選手(最大200人)を復号して、アプリの中で比べる。比べるときは前後の空白・全角半角・大文字小文字をそろえる |
| B | 表示名の照合用ハッシュ(HMAC)の列を足し、DB で探す |

推奨の理由:1チーム200人までなので、復号して比べても負担は小さい。B は照合用の列が増え、同じ名前の選手がいることが鍵なしでも列の一致から分かってしまう。

### 判断2. 名簿の閲覧の監査ログの粒度(AC-003-11)

| 案 | 内容 |
|---|---|
| **A(推奨)** | 一覧・1人の詳細を API で取得するたびに1件記録する。範囲(全員か自分の子どもだけか、絞り込みの条件、詳細なら選手ID)を残す |
| B | 同じ人・同じ範囲の閲覧は、1日1件にまとめる |

推奨の理由:spec の「誰が・いつ・どの範囲を」をそのまま満たす。チームの規模(200人、メンバー数十人)なら件数は問題にならない。まとめると、いつ見たかが分からなくなる。

### 判断3. CSV の「確認してから確定」の作り方(AC-003-14)

| 案 | 内容 |
|---|---|
| **A(推奨)** | 確認と確定で、同じファイルを2回送る。確認の応答でファイルのハッシュを返し、確定のときに同じハッシュかを確かめてから、もう一度検査して登録する。サーバーには途中の状態を残さない |
| B | 確認のときに読み込んだ行をサーバーに一時保存し、確定のときはその ID だけを送る |

推奨の理由:A ならサーバーに選手の名前を一時保存しない(ADR-0003)。ファイルは最大1MBなので、2回送っても負担は小さい。確定のときにもう一度検査するので、確認から確定までの間に名簿が変わっても(200人の上限など)正しく判断できる。

### 判断4. 保護者が見られる範囲:同じ選手に紐づく他の保護者(AC-003-09)

spec は「自分に紐づく選手だけが見られる。他の家庭の選手と保護者は見られない」としている。同じ選手に紐づく、もう1人の保護者(両親のもう一方など)を見せるかは決まっていない。

| 案 | 内容 |
|---|---|
| **A(推奨)** | 自分の子どもに紐づく他の保護者の表示名は見せる |
| B | 自分の子どもの情報だけを見せ、他の保護者は一切見せない |

推奨の理由:同じ子どもの保護者は同じ家庭とみなせる。誰が紐づいているかが分かると、紐づけの間違い(別の家庭の人が紐づいている)に保護者自身が気づける。

### 判断5. 選手の変更の監査ログと、削除の方法(ADR-0003)

spec の受け入れ基準は閲覧と取り込みの記録だけだが、ADR-0003 は「閲覧・変更・出力を監査ログに残す」としている。

| 案 | 内容 |
|---|---|
| **A(推奨)** | 登録・編集・削除・保護者の紐づけと解除も監査ログに残す(選手IDと変わった項目の名前だけ。値は残さない)。削除は行ごと消す |
| B | spec どおり、閲覧と取り込みだけを記録する。削除は論理削除(削除済みの印を付けて残す) |

推奨の理由:A は ADR-0003 に合う。削除した選手の名前を残す理由がないので、行ごと消す。監査ログに値を残さないので、消した名前が監査ログから読めることもない。spec に AC-003-20 として足す。

### 判断6. CSV の中の重複と、既存の選手との重複(AC-003-03 の延長)

| 案 | 内容 |
|---|---|
| **A(推奨)** | 確認の画面で、重複の可能性がある行(CSV の中の同じ表示名・同じ学年、または既存の選手と同じもの)を警告として示す。エラーではないので、確定はできる |
| B | 重複は警告しない(1人ずつの登録だけが AC-003-03 の対象) |

推奨の理由:年度初めに CSV を2回取り込んでしまう間違いを防げる。1人ずつの登録と同じ扱いになる。spec に AC-003-21 として足す。

### 判断7. CSV の文字コードの見分け方(AC-003-16)

| 案 | 内容 |
|---|---|
| **A(推奨)** | UTF-8 として正しく読めれば UTF-8(BOM は取り除く)、読めなければ Shift_JIS(Windows の拡張文字を含む CP932)として読む。どちらでもなければエラー |
| B | 画面で文字コードを選んでもらう |

推奨の理由:保護者会の役員の多くは、Excel で保存したファイルをそのまま使う。選ばせると間違えやすい。UTF-8 として正しく読めるかの判定は確実にできる。

## そのほかの方針(既存のADR・spec に沿うもの)

| 項目 | 内容 | 根拠 |
|---|---|---|
| 権限 | TeamPolicy に、選手の管理(代表・役員)、全員の名簿の閲覧(代表・役員・コーチ)、自分の子どもの閲覧(保護者)を足す | 004 の権限表、ADR-0011 |
| 他の家庭の選手 | 保護者が自分に紐づかない選手を ID で取得すると、存在しない場合と同じ404 | AC-003-10、AC-000-01 |
| 学年 | preschool / e1〜e6 / j1〜j3。画面とCSVでは「未就学」「小1」〜「中3」 | spec |
| 背番号 | 0〜999。任意。同じ背番号の重複は許す(学年違いで同じ番号がありうる) | spec |
| 上限 | 1チーム200人。CSV は500行・1MBまで。取り込みで200人を超えるなら1件も登録しない | AC-003-04・17 |
| 保護者の紐づけ | 1人の選手に4人まで。選べるのは、そのチームで保護者の役割を持つメンバーだけ | AC-003-05・07 |
| CSV の値 | `=` `+` `-` `@` で始まる値も、数式として扱わず文字列のまま保存する。CSV 出力(対象外)を作るときに、出力の側で無害化する | AC-003-18 |
| CSV の行番号 | 見出しを1行目として数える(Excel で見たときの行番号と同じ) | AC-003-15 |
| 個人情報 | 表示名は暗号化。ログ・例外・監査ログに表示名を出さない | ADR-0003 |

## データ(team-ops スキーマ、推奨案で書いた)

| 表 | 主な列 |
|---|---|
| players | id, team_id, display_name(暗号化), grade, number(NULL可), timestamps |
| player_guardians | id, player_id, membership_id。(player_id, membership_id) で一意 |

## 画面(案)

| 画面 | パス |

| 名簿(絞り込み、保護者には自分の子どもだけ) | /teams/:teamId/players |
| 選手の登録・編集・削除と保護者の紐づけ | /teams/:teamId/players/new、/teams/:teamId/players/:playerId |

## テスト

- API:受け入れ基準ごとの Feature テスト。権限は役割ごとの網羅
- テナント分離:他チームの選手、保護者から他の家庭の選手が404
- CSV:UTF-8(BOMあり・なし)、Shift_JIS、エラーの行・列・理由、上限、数式で始まる値、200人の上限
- ログ:選手の表示名がログに出ない
- Web:画面ごとに Testing Library
- E2E:代表が CSV を取り込む → 保護者を紐づける → 保護者は自分の子どもだけを見られる
