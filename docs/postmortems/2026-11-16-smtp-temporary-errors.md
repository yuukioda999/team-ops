# SMTP の一時エラーが2分続いても、全員にちょうど1通ずつ届いた

- 日付:2026-11-16
- 種類:障害訓練(spec 009 の AC-009-03)
- 判定:期待どおり
- 記録:https://github.com/yuukioda999/team-ops/actions/runs/43850003897(90日で消える)
- 確かめたコード:team-ops 9d1b2ae(PR のブランチの先頭)、team-ops-api ec04c8e(のちに作者だけを直して ecfbea5 と同じ中身)、notify-relay 7f60c9b(main)。このあと API は、送信ジョブの結果の書き方を直した(ffc3193 以降)。その版でも、同じ訓練を run 43856747950 で動かし、5種類とも期待どおりだった

## 概要

お知らせの公開の5秒前から2分間、Mailpit が 30% のメールに 451(一時エラー)を返すようにした。notify-relay は失敗したメールを再送し、障害を止めてから35秒で、3,000人全員にちょうど1通ずつ届いた。

## 影響

- 二重配信・取りこぼし:0
- 遅れ:2回目または3回目の送信で届いた宛先が 897人(617人が2回目、280人が3回目)。最後の1通は、予約の時刻から 155秒(障害がなければ数秒)
- 配信状況:最後はすべて「届いた」。受け取った回数・API・notify-relay を宛先ごとに並べて、食い違いなし

## 時系列(UTC)

| 時刻 | できごと |

| 10:37:55 | 障害を起こす(451 を 30%) |
| 10:38:00 | 予約の時刻。2秒後に最初の1通 |
| 10:40:00 | 障害を止める |
| 10:40:35 | 最後の1通(予約の時刻から155秒、障害を止めてから35秒) |
| 10:40:38 | 全員の結果が API・notify-relay・アウトボックスでそろう |

## どう気づいたか

- notify-relay のログに、`send attempt finished` が `error_code=provider_unavailable` 付きで 1,177件出た(INFO)。WARN や ERROR ではないので、警告だけを見ていると気づかない
- 配信状況では「送信中」が数分残る(訓練では画面を開いていない。画面の作りからの見立て)
- アラートの仕組みはまだない

## 原因

送信先(Mailpit)が一時エラーを返した。訓練で起こしたもの。

## どう戻したか

人は何もしていない。notify-relay が 30秒・2分の間隔で自動で再送した(AC-R001-10)。障害が2分で終わったので、10分以上の間隔の再送までは進まなかった。

## 次の手

- 一時エラーが続いていることに気づけるよう、失敗の割合をメトリクスかアラートにする(監視の spec で扱う。今回は範囲外)
- 再送を使い切って failed になる流れは、この訓練では確かめていない(判断3で、訓練用の設定を足さないことにした)
