# SMTP の一時エラーが2分続いても、全員にちょうど1通ずつ届いた

- 日付:2026-11-16
- 種類:障害訓練(spec 009 の AC-009-03)
- 判定:期待どおり
- 記録:https://github.com/yuukioda999/team-ops/actions/runs/43838162895

## 概要

お知らせの公開の5秒前から2分間、Mailpit が 30% のメールに 451(一時エラー)を返すようにした。notify-relay は失敗したメールを再送し、障害を止めてから36秒で、3,000人全員にちょうど1通ずつ届いた。

## 影響

- 二重配信・取りこぼし:0
- 遅れ:2回目または3回目で届いた宛先が 894人(620人が2回目、274人が3回目)。最後の1通は、予約の時刻から 157秒(障害がなければ数秒)
- 配信状況:途中は「送信中」が残り、最後はすべて「届いた」。API と notify-relay で食い違いなし

## 時系列(UTC)

| 時刻 | できごと |
|---|---|
| 09:19:55 | 障害を起こす(451 を 30%) |
| 09:20:00 | 予約の時刻。2秒後に最初の1通 |
| 09:22:01 | 障害を止める |
| 09:22:37 | 最後の1通(予約の時刻から157秒) |
| 09:22:42 | 全員の結果が API・notify-relay・アウトボックスでそろう |

## どう気づいたか

- notify-relay のログに、`send attempt finished` が `error_code=provider_unavailable` 付きで 1,168件出た(INFO)。WARN や ERROR ではないので、ログの警告だけを見ていると気づかない
- 配信状況の画面では、「送信中」が数分残る
- アラートの仕組みはまだない

## 原因

送信先(Mailpit)が一時エラーを返した。訓練で起こしたもの。

## どう戻したか

人は何もしていない。notify-relay が 30秒・2分の間隔で自動で再送した(AC-R001-10)。障害が2分で終わったので、10分以上の間隔の再送までは進まなかった。

## 次の手

- 一時エラーが続いていることに気づけるよう、失敗の割合をメトリクスかアラートにする(監視の spec で扱う。今回は範囲外)
- 5回の再送を使い切って failed になる流れは、この訓練では確かめていない(判断3で、訓練用の設定を足さないことにした)
