# 配信結果を受け取る API が2分止まっても、再開の約40秒後に配信状況がそろった

- 日付:2026-11-16
- 種類:障害訓練(spec 009 の AC-009-07)
- 判定:期待どおり
- 記録:https://github.com/yuukioda999/team-ops/actions/runs/43850003897(90日で消える)
- 確かめたコード:team-ops a25ccd9、team-ops-api ec04c8e、notify-relay 7f60c9b

## 概要

お知らせの公開の20秒前から公開の2分後まで、API を止めた。公開と送信は scheduler・worker・notify-relay が続けたので、3,000通は7秒で届いた。配信結果の webhook は API に届かず、notify-relay が送り直した。API が応答できるようになってから約40秒で、配信状況が3,000人とも「届いた」になった。

## 影響

- メール:二重配信・取りこぼしなし。遅れもなし
- 配信状況:API が止まっている間と、再開後の約40秒は、3,000人とも結果が出ていない状態(実際には届いている)。止まっている間に届いた結果は0件
- 受け取った回数・API・notify-relay は、最後に3,000人とも一致

## どう気づいたか

- notify-relay のログに `webhook was not accepted; will retry` が 400件(WARN)
- 配信状況で、届いているはずなのに「送信中」が残る(訓練では画面を開いていない。画面の作りからの見立て)。ただし API が止まっている間は、画面も開けない

## 原因

API が止まっていた。訓練で起こしたもの。

## どう戻したか

人は API を起動しただけ。notify-relay が webhook を 10秒から倍々の間隔で送り直した(AC-R001-19)。1時間ごとの照合(AC-006-09)を待つ必要はなかった。

## 次の手

- なし(期待どおり)。webhook の送り直しは最大1時間おきなので、長く止まると、そろうまで最大1時間かかる。手順書に書いた
