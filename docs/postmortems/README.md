# 振り返り(ポストモーテム)

障害訓練(spec 009、ADR-0025)と、実際に起きた障害の振り返りです。個人を責めず、仕組みとして何が起き、次に何を変えるかを書きます。

| 日付 | 振り返り | 結果 |
|---|---|---|
| 2026-11-16 | [SMTP の一時エラー](2026-11-16-smtp-temporary-errors.md) | 期待どおり。障害を止めて35秒で全員に1通ずつ |
| 2026-11-16 | [SMTP の恒久エラー](2026-11-16-smtp-permanent-errors.md) | 期待どおり。306人を再送せずに失敗として記録 |
| 2026-11-16 | [notify-relay の停止](2026-11-16-relay-stopped.md) | 期待どおり。手順どおり送り直すと5秒。ただし受け付けの deadlock で約6分遅れた回があった |

| 2026-11-16 | [配信結果を受け取る API の停止](2026-11-16-api-down-results.md) | 期待どおり。再開の約40秒後に配信状況がそろった |

## 雛形

ファイル名は `YYYY-MM-DD-<訓練または障害の短い名前>.md`。

```markdown
# <何が起きたか(1文)>

- 日付:
- 種類:障害訓練(spec 009 の AC-009-xx)/ 実際の障害
- 判定:期待どおり / 期待と違う
- 記録:GitHub Actions の run の URL(90日で消える)
- 確かめたコード:各リポジトリのコミット

## 概要
何を起こし、何が起きたか。3行ほど

## 影響
利用者から見て、何がどれだけ遅れたか・届かなかったか・二重に届いたか(数字で)

## 時系列(UTC)
起こした時刻、気づける時刻、戻した時刻、最初と最後の1通

## どう気づいたか
いまある手段(ログ・配信状況の画面・コマンド)で、どこに何が出たか。出なかったものも書く

## 原因
なぜそうなったか(作りのどこが、どうふるまったか)

## どう戻したか
人が何をしたか、仕組みが自動で何をしたか

## 次の手
直すこと・確かめること。直すかどうかは人間が決める(AC-009-09)
```
