# SMTP の恒久エラーの宛先は再送されず、配信状況に理由が出た

- 日付:2026-11-16
- 種類:障害訓練(spec 009 の AC-009-04)
- 判定:期待どおり
- 記録:https://github.com/yuukioda999/team-ops/actions/runs/43838162895

## 概要

Mailpit が 10% の宛先に 550(恒久エラー)を返すようにした。notify-relay は 296人を再送せずに失敗とし、API の配信状況にも「届かなかった(invalid_address)」と出た。ほかの 2,704人には、ちょうど1通ずつ届いた。

## 影響

- 届かなかった:296人。すべて送信1回で failed になり、再送していない
- 二重配信・取りこぼし(失敗と記録されずに届いていない宛先):0
- 配信状況:API と notify-relay で、3,000人とも状態が一致

|---|---|
| 09:19:55 | 障害を起こす(550 を宛先の 10%) |
| 09:20:00 | 予約の時刻。2秒後に最初の1通 |
| 09:20:06 | 最後の1通 |
| 09:20:08 | 全員の結果がそろう。障害を止める |

## どう気づいたか

- 配信状況の画面で、296人が「届かなかった」と理由付きで出る(これが利用者にとっての気づき方)
- notify-relay のログに `error_code=invalid_address` の行が 296件(INFO)

## 原因

送信先(Mailpit)が宛先を受け付けなかった。訓練で起こしたもの。

## どう戻したか

戻すものはない。恒久エラーは再送しても届かないので、設計どおり再送しない(AC-R001-11)。実際の運用では、本人にメールアドレスを直してもらう(手順書に書いた)。
