# ADR-0020: 既読、再通知、メールが届かないアドレス

- ステータス: 承認
- 日付: 2026-11-07
- 決定者: 小田 裕貴
- 関連: ADR-0003、ADR-0012、ADR-0016、ADR-0017、ADR-0018、ADR-0019、specs/006-read-and-delivery-status(判断3〜6・8)

## コンテキスト

- 既読は、アプリでお知らせを開いたときだけとする。メールの開封は記録しない(spec の既読の定義、ADR-0003)
- 未読の人にだけ再通知する。1時間に1回、1つのお知らせに3回まで(AC-006-11〜15)
- アドレスが原因で恒久的に届かなかった人には、本人に確認を促し、アドレスを変えたら送信対象に戻す(AC-006-16・17)

## 検討した選択肢

| 論点 | 採用した案 | 退けた案 |
|---|---|---|
| 恒久的な失敗 | **notify-relay の error_code が invalid_address のときだけ** | provider_rejected も含める(本人には直せない) |
| 届かないアドレスへの送信 | **アドレスを変えるまで、お知らせと再通知のメールを送らない(アプリには届く)。ログインのメールは送る** | 再通知だけ外し、新しいお知らせは毎回送る |
| 既読の記録 | **宛先の本人がお知らせの詳細を開いたとき** | 画面から「既読にする」API を別に呼ぶ |
| 再通知の記録 | **お知らせごとの再通知の表(回数・実行した人・人数・日時)** | お知らせの行に回数と最後の日時だけを持つ |
| 状況を見られる人 | **代表・役員はすべて、コーチは自分が作成したお知らせだけ。お知らせの画面から開く** | 送ったお知らせの一覧画面を別に作る(spec にない) |

## 決定

- 既読:宛先の本人がお知らせの詳細(GET)を開いたとき、既読日時が空なら入れる。一覧・状況の画面では入れない。作成者も宛先なので、自分のお知らせを開けば既読になる
- 届かないアドレス:お知らせ(再通知を含む)の結果が invalid_address なら、ユーザーに「メールが届かなかった日時」を入れる。ただし結果の発生日時が、そのユーザーの最後のメールアドレス変更より前なら入れない(古いアドレスの結果で新しいアドレスを止めない)。メールアドレスを変えたら消す
- 届かなかった日時がある人には、お知らせと再通知のメールを送らず、宛先の行を「送らなかった」にする。本人がアプリを開くと「メールが届いていません。メールアドレスを確認してください」と、変更画面への導線を出す
- 再通知:お知らせの行をロックし、前回から1時間以内、または3回済みなら 409 で次に実行できる時刻(3回済みなら null)を返す。実行時点の未読の宛先のうち、メールが届かないアドレスの人と、.invalid に限る環境で送れない人を除いて送る。除いた人数を返して表示する。未読が0人なら 409(画面ではボタンを押せない)
- 再通知のメール:件名「【再通知】【チーム名】タイトル」。重複防止キーは `team:{チームID}:notice:{お知らせID}:reminder:{回数}:part:{分割番号}`。送った人の宛先の行を送信待ちに戻す
- 再通知の表:notice_reminders(お知らせ、回数、実行した人、送った人数、除いた人数、実行日時)。監査ログ notice.reminded(回数・人数だけ)
- 失敗の理由の表示:invalid_address は「メールアドレスが存在しない可能性があります」、provider_rejected は「受信側のサーバーに受け取りを拒否されました」、provider_unavailable・rate_limited は「受信側のサーバーに一時的につながりませんでした」、expired は「送信期限を過ぎました」、送らなかった人は「メールが届かないアドレスのため送っていません」など。理由のコードは API で返し、文言は画面で決める
- 権限:TeamPolicy に viewNoticeStatus(お知らせ)を足す。代表・役員はすべて、コーチは作成者のときだけ。状況・未読者・失敗の一覧・再通知は同じ判定。権限表の 006 の行を PENDING から移す

## 結果

良くなること:

- 存在しないアドレスに送り続けないので、共通の送信元アドレスの評判を守れる
- 誰がいつ何人に再通知したかを後から確かめられる

悪くなること・受け入れるコスト:

- 一時的な不具合で invalid_address が返った場合も、本人がアドレスを変えるまで、お知らせのメールが止まる。アプリには届き、本人には表示で知らせる

## 見直す条件

- invalid_address の誤判定が実際に起き、同じアドレスのまま送信対象に戻す操作が必要になった場合
