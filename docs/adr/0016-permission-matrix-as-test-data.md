# ADR-0016: 権限表を API のテストのデータにする

- ステータス: 承認
- 日付: 2026-11-07
- 決定者: 小田 裕貴
- 関連: ADR-0011、specs/004-roles-and-permissions(判断1・7、AC-004-01)

## コンテキスト

- spec の補足:「権限表はテストのデータとしても使い、表とテストが食い違わないようにする」
- AC-004-01:権限表のすべての操作 × すべての役割で API を呼び、○の組み合わせだけが成功し、それ以外は403
- 権限表の正本は team-ops の spec.md。API の CI には team-ops のリポジトリがない
- 権限表には、まだ API のない操作(005 お知らせ、006 既読・配信状況)も入っている

## 検討した選択肢

| 論点 | 採用した案 | 退けた案 |
|---|---|---|
| 表の置き場所 | **API のリポジトリに、spec の権限表と同じ並びの表(PHP の配列)を置く** | テストの中で team-ops の spec.md を読む(CI で読めない) |
| まだない操作 | **005・006 を作るときに表へ足す** | 先に TeamPolicy に判定だけを作る |

## 決定

- `tests/Support/PermissionMatrix.php` に、操作ごとに「○の役割」と「API の呼び方」を書く。先頭に spec.md の権限表への参照を書く
- 網羅テストは、操作 × 役割(代表・役員・コーチ・保護者)のすべてで API を呼び、○なら成功、それ以外は 403 を確かめる
- TeamPolicy のすべての判定(public なメソッド)が表のどれかの操作に結び付いていることも確かめる。判定を足して表に足し忘れると、テストが落ちる
- spec の権限表を変えるときは、同じプルリクエストの組で表も変える(レビューで確かめる)

## 結果

良くなること:

- 権限の変更が表の1か所に集まり、レビューで差分を見やすい
- Policy の判定の足し忘れをテストで見つけられる

悪くなること・受け入れるコスト:

- spec.md と API の表の2か所に同じ内容がある。食い違いは機械では見つけられず、レビューで確かめる

## 見直す条件

- API の CI で team-ops のリポジトリを読めるようになった場合は、spec.md から表を作る方法を考え直す
