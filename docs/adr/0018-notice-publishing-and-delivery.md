# ADR-0018: 予約の公開と、お知らせの配信

- ステータス: 承認
- 日付: 2026-11-07
- 決定者: 小田 裕貴
- 関連: ADR-0002、ADR-0012、ADR-0017、specs/005-notice(判断4・5・7)、notify-relay の AC-R001-22

## コンテキスト

- 予約したお知らせは、指定日時になったら1分以内に公開し、メールの送信を始める(AC-005-11)
- notify-relay が止まっていても、お知らせは公開し、メールは復旧後に送る。同じ人に2通届けない(AC-005-07)
- 宛先が1,000人を超えたら、1,000人ずつに分けて依頼する(AC-005-08、notify-relay の上限)
- notify-relay は受付から7日で依頼を消す(AC-R001-22、T33)

## 検討した選択肢

| 論点 | 採用した案 | 退けた案 |
|---|---|---|
| 予約の公開 | **スケジューラで毎分、予約日時を過ぎたものを公開する** | 予約のときに、指定日時に実行するキューのジョブを入れる |
| 監査ログ | **送信・予約・予約の編集・取り消し・予約の公開を記録する。閲覧は記録しない** | 記録しない |
| relay の削除 | **1時間ごとに、受付から7日を過ぎた依頼を1,000件ずつ消す。最終状態でない宛先が残っていても消す** | 1日1回、決まった時刻に消す |

## 決定

- 公開の処理(今すぐ送信と、予約の公開で共通):お知らせの行をロックし、予約中であることを確かめてから、状態を公開済みにし、宛先を決めて保存し、アウトボックスに入れる。これを1つのトランザクションで行う。同時に2回動いても二重に公開しない
- スケジューラ:`notices:publish-due` を毎分実行する。予約日時を過ぎた予約中のお知らせを1件ずつ公開する
- 分割:宛先をユーザーIDの順に並べ、1,000人ずつに分ける。重複防止キーは `team:{チームID}:notice:{お知らせID}:part:{分割番号}`(アウトボックスの規約で、チームのデータには先頭にチームIDを付ける)。送り直しても同じキーなので、notify-relay が重複を除く(ADR-0002)
- メール:件名「【チーム名】タイトル」、本文にお知らせの本文とアプリで開くリンク。送信元は notify-relay の共通アドレス
- notify-relay が止まっているときは、アウトボックスの送り直し(outbox:redispatch)で、復旧後に送る
- 予約の公開の前に、作成者が今もチームにいて、作成できる役割を持つかを確かめる。どちらかでなければ公開せずに取り消し、監査ログ(notice.cancelled、理由つき)に残す(AC-005-17)
- 1件の公開に失敗しても、ほかの予約の公開を止めない。失敗はお知らせの ID と例外の種類だけをログに出し、次の分にやり直す
- スケジューラの重複起動の防止は、ロックの期限を5分にする(プロセスが落ちてロックが残っても、5分で公開を再開する)。二重の公開は行のロックで防ぐ
- 作成は1人1時間10件、人数確認は1人1分30回まで(AC-005-18)。全員宛ての送信を繰り返して、共通の送信元アドレスの評判を下げられないようにする
- 2026-11-07 のレビューを受けて、上の4項目と重複防止キーの形を追記した
- 監査ログ:notice.published、notice.scheduled、notice.updated、notice.cancelled。details はお知らせ以外の ID、宛先の種類、人数だけ。タイトル・本文は残さない
- notify-relay:1時間ごとに、受付から7日を過ぎた依頼を1,000件ずつ消す(宛先の行と重複防止キーも消える)。消した件数をログに出す

## 結果

良くなること:

- 予約の変更・取り消しで、ジョブの後始末が要らない
- スケジューラや notify-relay が止まっても、動き出したときに続きから公開・送信できる

悪くなること・受け入れるコスト:

- アウトボックスは24時間で送り直しをやめる。notify-relay が1日以上止まると、その間のお知らせのメールは送られない(お知らせ自体はアプリに公開される)

- 公開は最大で1分遅れる(spec の範囲内)
- 7日を過ぎた依頼は、notify-relay に照会しても見つからない(006 は webhook で受け取った結果を Laravel 側に持つ)

## 見直す条件

- 予約の件数が増え、毎分の処理が1分に収まらなくなった場合
