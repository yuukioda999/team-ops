# ADR-0021: デモモード

- ステータス: 承認
- 日付: 2026-11-08
- 決定者: 小田 裕貴
- 関連: ADR-0003、ADR-0012、ADR-0016、ADR-0018、ADR-0020、specs/007-demo-mode(判断1〜6)

## コンテキスト

- 面接官などの訪問者が、登録なしで全機能を試せるようにする。実在の人の情報が入らないこと、外部にメールが送られないことを最優先にする(spec 007)
- 訪問者ごとに専用のデモチームを作り、24時間で消す。訪問者どうしでデータは共有しない
- 名前・メールアドレスは暗号化とブラインドインデックスで保存している(ADR-0003)。デモ用のメールアドレスはチームごとに変える(`保護者1@demo-{チームID}.invalid`)

## 検討した選択肢

| 論点 | 採用した案 | 退けた案 |
|---|---|---|
| デモチームの作り方 | **架空のデータの定義(コード)から、ログインのたびに作る** | DB のテンプレートのチームを毎晩作り直し、行をコピーする(メールアドレスと暗号化のため結局作り直しが要る) |
| 削除の間隔 | **1時間ごとに、作成から24時間を過ぎたものを消す** | 毎晩1回(最長で約48時間残り、画面の「24時間後に削除」と合わない) |
| 送信されたメールの取り出し元 | **API が Mailpit の API に、宛先のドメインで問い合わせる** | API が送る前にメールの写しを自分の DB に残す(実際に届いたかが分からない) |
| デモユーザー | **チームごとに架空の代表・役員・コーチ・保護者を作り、役割の切り替えはそのユーザーへのログインし直し** | 訪問者用のユーザー1人の役割を書き換える(送信者・既読の表示が崩れる) |
| 止める操作 | **デモモードかどうかで止める** | デモユーザーのときだけ止める(デモ環境に実在の人が登録できてしまう) |
| 上限と監視 | **IP ごとに1時間20回、500チームで止めてエラーログ。数はログに残す** | 今すぐ OpenTelemetry のメトリクスで送る |

## 決定

- デモモードは `DEMO_MODE=true` のときだけ動く。デモモードでは `RECIPIENTS_INVALID_ONLY` も必ず有効にする(設定が false でも true として扱う)
- `POST /api/demo/sessions`(役割を指定):デモチームを1つ作り、選んだ役割のデモユーザーとしてログインする。デモモードでなければ 404
  - チームとユーザーに「デモの期限」(作成から24時間)を持つ。デモのユーザーはそのデモチームにだけ属する
  - 架空のデータ:代表1・役員1・コーチ2・保護者20、選手20(学年・保護者の紐づけ付き)、承認待ちの参加申請2、送信済みのお知らせ2(既読・未読・送信済みの状態付き)と予約中のお知らせ1。名前は実在の人物・チームと重ならない架空のもの。メールアドレスは `parent1@demo-{チームID}.invalid` のように名前の部分を英数字にする(日本語の名前の部分は、配信依頼の検査とメールの規格で使えないため。spec の補足も更新)
  - 作ったデモチームの ID をセッションに残す
- `POST /api/demo/sessions/switch`(役割を指定):セッションに残したデモチームの、指定した役割のデモユーザーとしてログインし直す。データはそのまま
- デモモードでは次を 403 にする。画面ではその入力欄やボタンを出さず、理由を表示する
  - マジックリンクの発行・使用
  - チームの作成
  - メールアドレスの変更
  - 招待からの参加申請(招待の発行・QR の表示はできる。承認は用意した申請で試す)
- 削除:`demo:prune` を1時間ごとに実行し、期限を過ぎたデモチームを消す。チームに付く行は外部キーで消え、デモユーザー、アウトボックスの行(tenant_ref)、Mailpit のメール(宛先のドメインで検索して削除)も消す。`make demo-reset` は期限に関係なくすべてのデモチームを同じ方法で消す
- 役割の切り替え(`POST /api/demo/sessions/switch`)は、デモモードでなければログインより先に 404 にするため、ログインをコントローラで確かめる
- 期限切れ:デモのセッションで、ユーザーが消えていれば 401 と `reason: demo_expired` を返す。画面はログイン画面に戻り「デモの有効期限が切れました」と表示する
- 送信されたメール:`GET /api/teams/{team}/demo/mails`。デモチームのメンバーだけ。API が Mailpit の API に `to:@demo-{チームID}.invalid` で問い合わせ、宛先がすべてそのドメインであるメールだけを、新しい順に件名・宛先・本文で返す。Mailpit の場所は設定(`MAILPIT_URL`)。デモモードでなければ 404
- 上限:作成は IP ごとに1時間20回(21回目から 429)。存在するデモチームが500以上なら 503 で作らず、エラーのログ(アラート)を出す
- 指標:作成・削除のたびに、作成数・削除数・存在する数をログに出す。メトリクスとしての送信は、監視の整備のときに行う
- サンプル CSV:架空の選手20人分を、名簿の CSV 取込の画面からダウンロードできる(デモモードに限らない)

## 結果

良くなること:

- 訪問者は登録なしで、役割ごとの見え方と、実際に届くメールを確かめられる
- デモのデータは定義が1か所なので、直すのも確かめるのも簡単

悪くなること・受け入れるコスト:

- デモ環境では Mailpit を本番の一部として動かす(外部には出さない)
- ログインのたびに約45人分の行を書くので、DB の書き込みが増える(上限で抑える)

## 見直す条件

- デモチームの作成が3秒を超える、または DB の負荷が問題になった場合
