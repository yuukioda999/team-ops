# ADR-0017: お知らせの保存と、宛先の決め方・持ち方

- ステータス: 承認
- 日付: 2026-11-07
- 決定者: 小田 裕貴
- 関連: ADR-0003、ADR-0011、ADR-0013、specs/005-notice(判断1〜3・6)

## コンテキスト

- お知らせは代表・役員・コーチが、全員・学年・役割のどれかに宛てて送る。予約もできる
- 本文には、子どもの名前や集合場所など、個人に関わることが書かれうる
- 006 で「何人中何人が読んだか」を出すため、送信時点の宛先を保存する(spec の補足)
- 本文は文字として表示し、URL はリンクにする(AC-005-16)

## 検討した選択肢

| 論点 | 採用した案 | 退けた案 |
|---|---|---|
| タイトル・本文 | **暗号化して保存する** | 平文で保存する(検索できる) |
| 宛先の持ち方 | **お知らせごとの宛先の表に、ユーザーIDで保存する。除名されても行は残す** | メンバーシップIDで保存し、除名で一緒に消す |
| 予約中のお知らせを見られる人 | **作成者と代表・役員** | 作成者だけ |
| URL のリンク化 | **`http://` と `https://` で始まるものだけ** | `www.` やメールアドレスもリンクにする |

## 決定

- notices:タイトル(1〜100文字)と本文(1〜2,000文字)は暗号化する。宛先の指定(全員/学年/役割と、その値)、状態(予約中/公開済み/取り消し)、予約日時、公開日時、宛先の人数を持つ
- 宛先は送信時点(予約なら公開の時点)の名簿で決め、notice_recipients(お知らせID、ユーザーID)に保存する。メールアドレスは持たない
  - 全員:チームの全メンバー
  - 学年:その学年の選手に紐づく保護者 + 代表・役員・コーチ全員
  - 役割:選んだ役割を持つメンバー
  - どれでも送信者本人を足し、同じ人は1回だけにする
- お知らせを見られるのは、宛先に含まれるメンバーだけ。宛先でないお知らせを ID で取得すると404(AC-005-15)。チームから除名された人は、チームのデータに入れないので見られない
- 予約中のお知らせは、作成者と代表・役員だけが一覧で見られ、編集・取り消しできる。宛先の人にも公開までは見せない
- 送信済みのお知らせは編集できない(409、AC-005-06)
- 本文の表示:HTML として解釈しない。`http://` と `https://` で始まる URL だけを `<a>` にし、新しいタブで開き、`rel="noopener noreferrer nofollow"` を付ける

## 結果

良くなること:

- DB が漏れても、お知らせの中身は読めない
- 006 の母数が、除名などのあとの操作で変わらない

悪くなること・受け入れるコスト:

- お知らせの本文を検索できない(必要になったら考え直す)
- 宛先の表は、メンバー数 × お知らせの数だけ行が増える(1チーム200人程度なら問題にならない)

## 見直す条件

- お知らせの検索が必要になった場合
- お知らせの保存期間を決める場合(ADR-0003 の個人情報の保存期間とあわせて決める)
