# ADR-0015: 役割の変更・代表の交代・除名の作り方

- ステータス: 承認
- 日付: 2026-11-07
- 決定者: 小田 裕貴
- 関連: ADR-0003、ADR-0011、ADR-0012、ADR-0013、specs/004-roles-and-permissions(判断2〜6・8)

## コンテキスト

- 1人が複数の役割を持て、代表は各チームに1人だけ。役割が1つもない状態は作れない(AC-004-09)
- 代表は役割の変更・代表の交代ができる。代表と役員はメンバーを除名できるが、役員は代表と他の役員を除名できない(AC-004-07)
- 役割の変更は本人に、代表の交代は両者にメールで知らせる(AC-004-03・04)。除名の通知は受け入れ基準にない
- 権限表の「チーム名・競技の変更」「監査ログの閲覧」には、まだ API がない

## 検討した選択肢

| 論点 | 採用した案 | 退けた案 |
|---|---|---|
| 役割の変更の形 | **役割の一覧をまるごと置き換える。代表は含められない。空の一覧は受け付けない** | 1つずつ足す・外す。最後の1つを外すと確認つきで除名する |
| 代表の交代 | **新しい代表は役員を外して代表を付ける。元の代表は代表を外して役員を付ける。コーチ・保護者はそのまま** | 新しい代表は役員と代表の両方を持つ |
| 除名 | **メンバーの行を消す(役割と選手の紐づけも消える)。再申請できる。本人にメールしない** | 除名の印を付けて残し、再申請を断る。本人にメールする |
| メンバー一覧 | **代表と役員だけが見られる。表示名と役割だけ** | メンバー全員が見られる |
| チーム名・競技の変更、監査ログの閲覧 | **004 で作る(AC-004-11・12 を追加)** | 作らない、または第2弾に回す |

## 決定

- 役割の変更:`PUT /teams/{team}/members/{membership}/roles` に、代表を除く役割の一覧を送る。空なら 422(「役割をすべて外すと除名になります」)。画面は、すべて外そうとしたときに除名の確認を出す
- 保護者の役割を外すと、そのメンバーと選手の紐づけも一緒に外す(判断8)。外した数を監査ログに残す
- 代表の役割は交代でしか動かない。そのため「代表が自分の代表を外す」は API の形で起きない(AC-004-06)。代表が自分を除名しようとした場合は 422(「先に代表を交代してください」)
- 代表の交代:役員の役割を持つメンバーだけを指定できる。それ以外は 422(「先に役員に任命してください」、AC-004-05)。入れ替えは1つのトランザクションで行い、代表が0人や2人の瞬間を作らない
- 除名:役員が、代表または役員の役割を持つメンバーを除名しようとすると 403(AC-004-07)。この判定は TeamPolicy に置く
- 役割はリクエストのたびに DB から読む。キャッシュしないので、変更は次のリクエストから効く(AC-004-10)
- メール:役割の変更(本人)、代表の交代(両者)。アウトボックス経由で、重複防止キーを付ける(ADR-0002)。文面にはチーム名と新しい役割だけを入れる
- 監査ログ:member.roles_changed(変更前と変更後の役割)、team.representative_transferred、member.removed(除名した人の役割)、team.updated(変わった項目の名前)。details に表示名は入れない(ADR-0012)
- 監査ログの閲覧:新しい順に100件ずつ。日時・操作した人の表示名・操作の種類(日本語)を表示する。details の ID は表示しない。操作した人がすでにチームにいない場合は「(退会したメンバー)」と表示する

## 結果

良くなること:

- 役割を変える操作と除名が分かれ、記録・メールの場所がそれぞれ1か所になる
- 代表が必ず1人いる状態を、API の形と一意制約の両方で守れる

悪くなること・受け入れるコスト:

- 除名した記録はメンバーの行に残らない。監査ログにだけ残る
- 間違って除名した場合は、もう一度申請してもらい承認する必要がある

## 見直す条件

- 除名を本人に知らせる必要が出た場合(spec に足してから、文面を決める)
