# ADR-0008: ログインはマジックリンクとし、リンクは確認画面のボタンで使う

- ステータス: 承認
- 日付: 2026-11-05
- 決定者: 小田 裕貴
- 関連: ADR-0002、ADR-0003、specs/001-account-and-team

## コンテキスト

- 保護者に「パスワードを忘れた」対応をさせたくない。spec 001 でパスワードなしのログイン(マジックリンク)と決めている
- リンクは15分で失効し、2回目は使えない(AC-001-04)
- 会社や携帯会社のメールには、届いたメールのリンクを安全確認のために自動で開く仕組みがある。本人より先にリンクが開かれることを前提にする必要がある
- Web と API は同じオリジンで動く(Vite・nginx のプロキシ)。ブラウザのJSに認証トークンを持たせたくない

## 検討した選択肢

リンクを開いたときの動作:

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | **リンクは確認画面を開くだけ。画面の「ログインする」ボタン(POST)でトークンを使う** | **自動確認で開かれてもトークンは残る。タップが1回増える** |
| B | リンクを開いた時点(GET)でトークンを使ってログインする | タップは最少だが、自動確認でトークンが使い切られ、本人がログインできなくなる |

ログイン後の状態の持ち方:

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | **Laravel Sanctum の SPA 認証(Cookieのセッション、CSRF対策付き)** | **同じオリジンなら最も安全で単純。トークンをJSに持たせない** |
| B | APIトークンを発行し、ブラウザの localStorage に保存する | 将来のスマホアプリには向くが、XSSでトークンが盗まれうる |

## 決定

両方とも案Aを採用する。

- ログイン用トークンは32バイトの乱数。DBには SHA-256 のハッシュ値だけを保存する。15分で失効し、使ったら直ちに無効にする
- メールのリンクは Web の確認画面(`/login/verify?token=...`)を開く。トークンを使うのは、画面のボタンから `POST /api/auth/login-links/consume` を呼んだときだけ
- ログイン後は Sanctum の SPA 認証でセッションを持つ。最後の操作から30日で失効する。ログイン時とログアウト時にセッションIDを再発行する
- ログイン用リンクの要求は、メールアドレスのハッシュ値ごとに1時間5回まで。IPごとの制限も別にかける
- 登録済みかどうかで応答の内容と時間を変えない(送信はキューに積み、すぐ応答する)
- ログイン用メールも notify-relay 経由で送る(ADR-0002)

## 結果

良くなること:

- パスワードを預からないので、パスワード漏えいとリセット対応がなくなる
- 迷惑メール対策の自動確認があっても、本人がログインできる
- 認証トークンがJSから読めないので、XSSの被害を小さくできる

悪くなること・受け入れるコスト:

- ログインのたびにメールを開く必要があり、メールが遅れるとログインも遅れる。送信の速さと状態を notify-relay のメトリクスで見る
- 確認画面のぶん、タップが1回増える
- 将来スマホアプリを作る場合は、トークン方式を別に用意する必要がある

## 見直す条件

- メールが届かない・遅いという問い合わせが続く場合(ワンタイムコードの併用を検討する)
- スマホアプリを作る場合
