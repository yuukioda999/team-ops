# ADR-0019: 配信結果の受け取りと照合

- ステータス: 承認
- 日付: 2026-11-07
- 決定者: 小田 裕貴
- 関連: ADR-0002、ADR-0003、ADR-0004、ADR-0017、ADR-0018、specs/006-read-and-delivery-status(判断1・2・7)、notify-relay の AC-R001-16〜21

## コンテキスト

- 006 は、お知らせごとに誰に届かなかったか、まだ送っている途中かを表示する(AC-006-04〜08)
- 宛先ごとの結果は notify-relay だけが知っている。notify-relay は Laravel の DB を読まず、Laravel も notify-relay の DB を読まない(ADR-0004)
- notify-relay の OpenAPI には結果の webhook と状態の照会が定義されているが、まだ作っていない
- notify-relay は受付から7日で依頼を消す(ADR-0018)。それより後に結果を知る方法はない

## 検討した選択肢

| 論点 | 採用した案 | 退けた案 |
|---|---|---|
| 結果の受け取り | **notify-relay が webhook で宛先ごとの結果を送る(AC-R001-16〜20)。照会(AC-R001-21)は照合だけに使う** | Laravel が定期的に照会する(照会は件数だけなので、誰が失敗したか分からない) |
| 宛先ごとの状態の持ち方 | **お知らせの宛先の行(notice_recipients)に配信状態・失敗の理由・結果の発生日時を持つ** | 依頼×宛先ごとの結果の表を別に持ち、表示のたびに集計する |
| 照合 | **1時間ごとに、完了の通知が来ていない依頼を照会し、件数が食い違えば記録してエラーログを出す** | 食い違いを見つけたら、宛先ごとの結果を notify-relay に送り直させる |

## 決定

notify-relay:

- 宛先が最終状態(delivered / failed / skipped)になったら、依頼ごとに500件または5秒のどちらか早いほうでまとめて `delivery.results` を送る。依頼の全宛先が最終状態になり、その結果をすべて送ったら `delivery.completed` を1回送る
- 送るイベントは、作った時点で notify-relay の DB に保存してから送る(プロセスが落ちても失わない)。宛先の行には「結果を送るイベントに入れた」ことを記録し、二重に入れない
- 送り先は設定で固定する(WEBHOOK_URL)。署名は配信 API と同じ方式で、鍵は設定の WEBHOOK_KEY_ID のもの。依頼に traceparent があれば付ける
- 2xx 以外・10秒で応答なしは、指数バックオフで最大24時間送り直す。401 は送り直さない。どちらも諦めたらエラーログ(アラート)
- 状態の照会(GET /v1/deliveries/{id})は件数だけを返す。7日を過ぎた依頼は 404
- イベントは依頼と一緒に7日で消える

Laravel:

- notify-relay が受け付けたときに返す delivery_id を、アウトボックスの行に保存する(照合に使う)
- webhook の受け口(POST /api/internal/notify-relay/events)は、署名と時刻(5分以内)を確かめる。セッション・CSRF は使わない。event_id を表に保存して、同じイベントは何もせず 204 を返す
- 重複防止キーからお知らせを、recipient_ref(`user_{ID}`)から宛先の行を見つけて、配信状態を更新する。お知らせ以外のメール(ログイン・招待など)の結果は受け取って捨てる
- 配信状態:送信待ち(pending)・送信済み(delivered)・失敗(failed)・送らなかった(skipped)。結果の発生日時が、行にある発生日時より古ければ採らない(到着順は保証されないため。再通知の結果も同じ行を更新する)
- 宛先を .invalid に限る環境、またはメールが届かないアドレス(ADR-0020)の人には、送信の時点で「送らなかった」にする
- お知らせの状況:宛先の行に送信待ちが残っていれば「送信中」
- 照合:`notices:reconcile-deliveries` を1時間ごとに実行する。お知らせのアウトボックスのうち、notify-relay に渡してから1時間を過ぎ、まだ送信待ちの宛先がある依頼を照会する。notify-relay の件数(最終状態の数)と Laravel 側の件数が食い違えば、照合の記録を残してエラーログを出す。404(7日を過ぎた)の依頼はそれ以上照会しない。宛先ごとの状態は照会では直さない

## 結果

良くなること:

- 結果は宛先ごとに Laravel 側に残るので、notify-relay が7日で依頼を消しても状況を表示できる
- 既読と配信状態を同じ行で数えられる

悪くなること・受け入れるコスト:

- notify-relay に、イベントの保存と送り直しの仕組みが増える
- webhook が24時間届かなかった結果は、照合で食い違いとして分かるだけで、宛先ごとには直らない(その人の状態は送信待ちのまま)

## 見直す条件

- 照合の食い違いが続けて起き、宛先ごとに直す必要が出た場合
