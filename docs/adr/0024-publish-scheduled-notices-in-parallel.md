# ADR-0024: 予約のお知らせを、お知らせごとのジョブで並列に公開する

- ステータス: 承認
- 日付: 2026-11-13
- 決定者: 小田 裕貴
- 関連: ADR-0018(予約の公開)、ADR-0023(負荷試験の方法)、specs/008-load-test(直し方の段階2)

## コンテキスト

- 予約のお知らせは、scheduler が毎分 `notices:publish-due` を動かし、時刻の来たものを1件ずつ順に公開していた(宛先の決定と保存、アウトボックスへの書き込み)
- 負荷試験(1万チーム)では、1万件の公開に 186〜311秒かかった。worker を4つにした段階1のあと、全体の試験で2番目に長い段階になっている(loadtest/README.md)
- 公開は1件ずつ行をロックして状態を確かめ直す作りなので、同時に動いても二重に公開しない(ADR-0018)

## 検討した選択肢

| 案 | 内容 |
|---|---|
| **A(採用)** | scheduler は時刻の来たお知らせを、1件ずつ公開のジョブにしてキューに積むだけにする。公開は worker が並列に行う |
| B | scheduler の中で、複数のプロセスを起こして並列に公開する。プロセスの管理を自分で書くことになり、worker の数とも別に調整が要る |
| C | 公開の処理そのものを速くする(宛先の保存をまとめて insert する など)。1件あたりは速くなるが、順に処理する作りは変わらない |

## 決定

- `PublishDueNotices` は、時刻の来た予約中のお知らせを `PublishScheduledNoticeJob`(お知らせの ID だけを持つ)にして積む
- 公開そのものは `PublishScheduledNotice` が行う。今までどおり、行をロックして状態を確かめ直し、作成者が作成できなければ取り消す
- 同じお知らせのジョブは、処理が終わるまで1つしか積まない(`ShouldBeUnique`、最長10分)。キューが混んでいて次の分の scheduler がまた積もうとしても重ならない。重なっても、公開は1回だけになる
- ジョブは失敗してもやり直さず、エラーのログ(本文や宛先は出さない)を出す。次の分の scheduler がもう一度積む

## 結果

良くなること:

- 公開が worker の数だけ並列になる。worker を増やせば、公開もアウトボックスの送信も速くなる
- scheduler の1回の処理が短くなり、ほかの定期処理を待たせない

悪くなること・受け入れるコスト:

- 公開の時刻が、キューの混み具合に左右される(予約の時刻から、worker が拾うまでの時間が足される)
- 公開とアウトボックスの送信が同じ worker を取り合う

## 見直す条件

- 公開の待ちが、AC-005-11(予約の時刻から1分以内に公開)を満たさなくなった場合。キューを公開用と送信用に分けることを考える
