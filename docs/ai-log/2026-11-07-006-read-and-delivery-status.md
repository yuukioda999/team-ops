## 3. AIの出力

- **plan.md**:判断8件(relay の webhook をどこで作るか、宛先ごとの状態の持ち方、恒久的な失敗の範囲、届かないアドレスを以後のメールから外すか、既読の記録、再通知の記録、照合の範囲、見られる人と画面の場所)
- **ADR**:2件(配信結果の受け取りと照合、既読・再通知・届かないアドレス)
- **relay**:結果のまとめ(500件または5秒)、完了の通知、イベントを保存してから送る、署名・traceparent・24時間の送り直し・401 は送り直さない、状態の照会

- **E2E**:送る → 結果が webhook で届く → 1人が読む → 未読の人にだけ【再通知】が届く

## 6. AIが間違えた点と学び

- **完了の通知を、結果を送る前に作っていた(R1)**
  - relay は結果をイベントに入れた時点で完了も作り、両方を並行に送っていた。完了が先に届くと、Laravel は照合をやめてしまい、結果が欠けても気づけなかった
  - 学び:「すべて終わった」を知らせるイベントは、その前のイベントが届いたことを条件にする。受け手の側でも件数を突き合わせる
- **別々のマシンの時計で前後を決めていた(R3)**
  - 送信待ちにした時刻(Laravel)と結果の発生時刻(relay)を比べていた。時計がずれると、正しい結果を捨てたり、古い結果で上書きしたりする
  - 学び:前後は同じ発生元の時刻どうし、または送信の通し番号で決める
- **古いアドレスの失敗で新しいアドレスを止めうる条件だった(S1)**
  - ADR には「古いアドレスの結果で新しいアドレスを止めない」と書いたのに、比べる時刻を結果の発生日時にしていた。送信が遅れたときに守れない
  - 学び:「どの時点の値で送ったか」を基準に比べる。ADR に書いた約束ごとに、それを破る筋書きをテストにする
- **チームを抜けた人の表示名を、spec にないまま返していた(S2)**
  - 一覧に「チームにいません」と付けて残したのは、AI の判断だった。人間に確認していなかった
  - 学び:個人情報を見せる範囲を広げる判断は、実装の前に plan で確認する
- **006 より前のデータの扱いを考えていなかった(R2)**
  - 新しい列の初期値「送信待ち」のまま、005 で送ったお知らせがずっと送信中に見えるところだった
  - 学び:列を足すときは、既存の行がどう見えるかを plan に書く
- **401 を広く返していた(S3)**
  - 受け手が 401 を返すと relay は送り直さない。時計のずれや設定漏れでも 401 にしていたので、一時的な事故で結果を失うところだった
  - 学び:エラーの種類は、相手がそれを見てどう動くか(送り直すか)で選ぶ
- **CLAUDE.md の決まり(Resource)を守っていなかった(R4)**
  - 状況・一覧・再通知を、UseCase の配列のまま返していた
  - 学び:新しい API を足したら、応答が Resource を通っているかを自分で確かめてからレビューに出す
- **E2E とスクリーンショットで、読み込み中の画面を見ていた**
  - 「未読が0件」を数えただけの確かめ方は、一覧を読み込む前でも通ってしまい、未読のままのスクリーンショットを1枚撮り直した
  - 学び:「ないこと」を確かめる前に、まず「あるべきもの」が表示されるのを待つ
