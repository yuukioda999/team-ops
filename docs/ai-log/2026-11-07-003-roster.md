## 5. 判断(人間が決めたこと)

| 判断 | 内容 |
|---|---|
| 1 | 重複は、同じ学年の選手(最大200人)を復号して比べる。照合用のハッシュの列は作らない |
| 2 | 名簿の一覧・詳細を開くたびに監査ログを1件残す |
| 3 | CSV は確認と確定で同じファイルを2回送る。サーバーに名前を一時保存しない |
| 4 | 保護者は、自分の子どもと、その子に紐づく他の保護者の表示名を見られる |
| 5 | 登録・編集・削除・紐づけも監査ログに残す(値は残さない)。削除は行ごと消す |
| 6 | CSV の中と既存の選手との重複は、エラーではなく警告にする |
| 7 | UTF-8 として読めなければ CP932 として読む |
| レビュー | S1(大量の短い行でメモリ不足)、S2(権限より先に入力を検査)、S3(確認が記録に残らない)ほか、14件を直した |

## 6. AIが間違えた点と学び

- **CSV の行を全部読んでから上限を判定した(S1)**
  - 1MB 以内でも短い行を大量に並べると、メモリを使い切って API が落ちた。セキュリティのレビューで、実際に再現して指摘された
  - 学び:上限は「読み終えてから数える」のではなく、「超えた時点で読むのをやめる」形で書く。誰でも代表になれる仕組みでは、代表だけの操作も攻撃の入口になる
- **FormRequest の検査が、Controller の権限の判定より先に動くことを見落とした(S2)**
  - 権限のない人にも 422 が返っていた。テストが正しい内容しか送っていなかったので気づけなかった
  - 学び:権限のテストでは、不正な内容を送っても403になることも確かめる
- **確認の操作を監査ログに残さなかった(S3)**
  - 確認は既存の名簿と照らした結果を返すので、閲覧と同じ意味を持つ。登録しない操作だからと記録の対象から外していた
  - 学び:「データを返すか」で記録の要否を判断する
- **絞り込みを同じ条件で押すと止まる不具合(レビューの指摘1)**
  - React の状態に同じオブジェクトを渡し、再読み込みが動かなかった。テストも条件を変える場合しか書いていなかった
- **SQLite で意味のないテスト(レビューの指摘3)**
  - 監査ログに名前がないことを生の JSON で確かめていたが、SQLite は日本語を `\uXXXX` で保存するので、名前が入っていても通った
  - 学び:保存の形式に依存しないよう、読み出してから比べる
- **Node のバージョンの違いで CI だけ落ちた(マージの段階)**
  - 作業環境は Node 22、CI は Node 24。Node 24 では、テストの中で jsdom の File を送ると中身が空になり、CSV の画面のテストが CI だけで落ちた。レビューのあとに見つかったため、テストの共通部品を直してからマージした(画面のコードは変えていない。修正の内容はコミット「make the CSV upload tests work on Node 24」)
  - 学び:作業環境のバージョンを CI と合わせる。合わせられないときは、CI と同じバージョンでも一度テストを動かす
- **E2E で API を直接呼ぶ方法を誤った**
  - Playwright の request は Referer を送らないため、ログインしていない扱いになった。画面の中から fetch するように直した。その途中で、未ログインで Accept を付けずに API を開くと 500 になる既存の不具合(001)を見つけ、範囲外として人間に報告した
